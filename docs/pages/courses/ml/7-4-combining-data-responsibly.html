7.4 Combining Data Responsibly

Does the model work for everyone? A fairness check by group, how combining Fitbit and proteomics shrinks the sample, whether steps add to prediction, and reporting with TRIPOD+AI

Machine learning series, class 4 of 4 · R · 95 minutes

Open the notebook on GitHub Machine learning series overview

Overview

A model with a good AUC isn’t finished. Before anyone uses it, three questions remain:

  1. Does it work equally well for everyone? An AUC is an average: a model can rank one group well and another poorly, or be right on average and wrong for a group.
  2. Is more data better? Each extra kind of data (a Fitbit, a blood sample) adds information, but only some people have it. Combining data shrinks the sample, and changes who is in it.
  3. Can someone else check it? TRIPOD+AI is the checklist for reporting a prediction model.

By the end you’ll be able to

  1. Check a model’s discrimination and calibration in each group
  2. Ask who a model would flag, and whose future cases it would miss
  3. Count how combining data types shrinks the sample, and changes who is in it
  4. Test whether Fitbit steps add to enrollment data, with cross-validation and the bootstrap
  5. Report a model with the TRIPOD+AI checklist

Key concepts

Three ways a model can be unfair

Check Asks A problem looks like
Discrimination in each group Within this group, does the model rank future cases above others? AUC 0.78 for one group, 0.65 for another
Calibration in each group Does the average predicted risk match the share diagnosed? predicted 5%, observed 8%: the group’s risk looks lower than it is
Who gets flagged If a program reached the top 10% of risk, what share of each group’s future cases would it reach? 35% of one group’s cases, 15% of another’s

Observed ÷ expected (O/E) sums up calibration: 1 is right; above 1, the model under-predicts for that group.

Why groups can differ: fewer people to learn from; a predictor that means different things in different groups; and an outcome that depends on care: someone who sees a doctor less often is diagnosed later, or not at all.

Small groups can’t be checked. Groups with fewer than 50 new cases are combined: they’re not audited, which is a limitation to report, not a reassurance.

Within an age group, the AUC drops: that’s expected

Part of the overall AUC comes from ranking older people above younger ones. Within one age group, that help is gone, so the AUC is lower. It’s a property of the AUC, not unfairness. Calibration and “cases reached” are better fairness signals for age.

The cost of combining data

+ Fitbit               ████████                                  people who shared a Fitbit
+ proteomics           █                                         people chosen for proteomics
+ Fitbit + proteomics  ▏                                         both: very few

Each combination’s time zero is the latest of its data dates. The people left may differ from everyone else (younger, wealthier, more active), and a model built on them describes a different population.

Reporting: TRIPOD+AI

TRIPOD+AI is a 27-item checklist for reporting prediction models, whether built with regression or machine learning. It supersedes TRIPOD 2015, and puts particular emphasis on fairness (Collins and others, BMJ, 2024, doi:10.1136/bmj-2023-078378).

Item Asks for In this series
3c known health inequalities between groups 7.4 Part 3; Precision Medicine
5a, 5b the data source, its representativeness, and the dates All of Us CDR v9; proteomics selection unknown (7.3)
8a the outcome, its time horizon, and how it’s assessed a first type 2 diabetes code within 2 years of time zero
9b each predictor: how and when it was measured at enrollment (7.1); the blood draw (7.3); Fitbit’s first 6 months (7.4)
10 why the sample size was enough the data check; events per predictor (7.3)

Not yet reported: external validation; model updating (items 12f, 24); and patient and public involvement (item 19): no participants helped design these models.

Code walk-through

Protecting counts that add up to a total

hide_with_total <- function(n, also = FALSE) {
1  hidden <- n <= 20 | also
2  while (any(hidden) && !all(hidden) && sum(n[hidden]) %in% 1:20) {
    hidden[which.min(replace(n, hidden, Inf))] <- TRUE
  }
  replace(n, hidden, NA)
}
1
Counts of 1 to 20 are hidden, plus any marked for another reason (also).
2
The groups add up to a known total, so the hidden ones’ sum can be worked out. If that sum is 1 to 20, hide the next smallest too, until it isn’t.

  data %>%
    mutate(horizon_end = time_zero + round(365.25 * HORIZON_YEARS),

Instructor notes

  • Ask for guesses first: which group will the model work worst for? Then run Part 3.
  • Explain the age-group AUC drop before anyone calls it unfair.
  • “Smaller groups, combined” is a finding: some groups can’t be audited with these numbers.
  • Race and ethnicity are social categories: differences can reflect access to care and diagnosis, not biology. Keep the discussion on what the model does, and to whom.
  • Close the series: time zero, the data type, and the people included mattered more than the method.

Key takeaways

  • An overall AUC can hide weaker performance in a group: check discrimination, calibration, and who gets flagged, by group.
  • Small groups can’t be audited reliably: say so.
  • Combining data types shrinks the sample and changes who is in it.
  • A predictor can be strongly associated with the outcome and still add little to prediction.
  • Report models with TRIPOD+AI.
