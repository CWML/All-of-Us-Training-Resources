4.6 Proteomics: Blood Proteins in Type 2 Diabetes

Olink proteins in plasma: reading only what you need from a 2.6 GB file, QC and batch checks, differential abundance with limma, and pQTLs

Omics series, class 6 of 7 · R (limma) · 120 minutes

Open the notebook on GitHub Omics series overview Omics for Beginners

Overview

Proteins are what the body builds and uses: hormones, enzymes, signals. All of Us has measured about 5,400 proteins in blood plasma from about 10,000 participants, with the Olink platform. We ask which proteins are higher or lower in type 2 diabetes, check that the data’s normalization worked, and look at whether the proteins’ levels are set partly by genetics (pQTLs).

Why this class matters

Blood proteins come from organs all over the body, so they can show what’s happening in the kidney, liver, or fat tissue, which blood RNA (4.5) can’t. That makes them promising biomarkers. The class also teaches practical skills for big data: reading only the rows you need from a huge file, and checking for batch effects in data that was normalized before you got it.

By the end you’ll be able to

  1. Explain how Olink measures proteins, and what an NPX value is
  2. Read only the rows you need from a very large file, with awk
  3. Apply QC flags, reshape long data into a matrix, and check for batch effects
  4. Run differential abundance with limma, and read the results
  5. Look up pQTLs in All of Us’s results

Analysis at a glance

❓ Questions Which plasma proteins differ in type 2 diabetes, and are their levels partly genetic?
🧪 The analysis A linear model per protein with limma on NPX, adjusted for age and sex, after QC and checks of normalization and plate effects; then a pQTL lookup
🎯 Why NPX is already normalized and log₂, so linear models fit directly; but leftover plate effects can look like biology, so we check; ~5,400 proteins, so FDR
✅ What we conclude Which proteins differ and which organs they point to; which have strong pQTLs
⚠️ What it can’t tell us Cause vs consequence vs treatment; for sure which organ a protein came from
🔗 Connections RNA in 4.5; both in 4.7. pQTLs + GWAS = Mendelian randomization

Key concepts

How Olink measures proteins

Pairs of antibodies, each carrying a short DNA tag, bind the same protein. Only when both bind are their tags close enough to join into a DNA sequence, which is counted by sequencing. More protein, more counts. The All of Us platform, Olink Explore HT, measures about 5,400 proteins (assays) from one small sample.

NPX, and what’s already been done

NPX (Normalized Protein eXpression) is on a log₂ scale (1 = twice as much) and is relative: compare the same protein between people, not two proteins. It’s already normalized twice: to control samples on each plate (by Olink’s software), and across batches of plates (by All of Us). So we don’t normalize again, but we check that no plate stands out.

Limit of detection

Below its limit of detection (LOD), an assay can’t tell signal from noise. The All of Us file we use doesn’t seem to include an LOD column, so the class explains it rather than filtering on it: treat “significant” proteins with a very low average NPX with caution.

Code walk-through

Reading only our people’s rows

wanted   <- c("ResearchID", "SampleID", "PlateID", "OlinkID", "UniProt", "Assay", "NPX", "SampleQC", "AssayQC")
1col_nums <- match(wanted, npx_columns)

awk_command <- str_glue(
2  "gzip -dc {shQuote(NPX_FILE)} | ",
3  "awk -F'\\t' -v OFS='\\t' -v id={col_nums[1]} ",
4  "'NR==FNR {{keep[$1]; next}} FNR==1 || ($id in keep) {{print {str_c('$', col_nums, collapse = ', ')}}}' ",
  "{shQuote(ids_file)} -"
)
5npx_long <- data.table::fread(cmd = awk_command, sep = "\t", header = TRUE)
1
The positions of the columns we need (awk refers to columns by number).
2
Uncompress the 2.6 GB file as it’s read, without saving an uncompressed copy.
3
Tell awk the columns are separated by tabs, and which column holds the participant ID.
4
First read our 600 IDs into a list called keep; then print the header, and every line whose ID is in keep, keeping only the columns we need. ({ } is how str_glue() writes a literal brace.)
5
fread() runs the command and reads the result into R: about 3 million rows instead of over 50 million.

What we found

Results from our test run in October 2026 (CDR v9), 300 cases and 300 controls.

People with proteomics 1,446 cases, 6,154 controls
Loading 3.5 minutes; about 32.5 million rows read, 5,420 proteins
QC over 99% of measurements passed; under 1% failed; a few WARN (kept, per Olink’s advice)
Batch checks 120 plates; plate explained essentially none of PC1–PC5 (adjusted R² ≤ 0); plate medians within about half an NPX unit
Outliers a few people (fewer than 20) flagged by the 5-SD rule: checked with a sensitivity analysis, not deleted
Significant proteins about 280–290, most of them higher in diabetes
Sensitivity: plate in the model 182 significant; logFC correlation with the main analysis 0.93
Sensitivity: outliers removed 533 significant; logFC correlation 0.995
Pathways (GO) up in diabetes: inflammation and defense and metabolism (organic acid, small molecule metabolism)
Leptin, BMI challenge logFC 0.68 without BMI (adjusted p ≈ 0.00007) → 0.18 with BMI (p ≈ 0.63): mostly body size
Top protein NFASC (higher in diabetes)
pQTLs 18 of the top 20 proteins had very strong pQTLs
rs7903146 not in any fine-mapped pQTL

The proteins point to organs:

Organ Proteins A possible story
Kidney HAVCR1 (KIM-1) and PDZK1 higher; UMOD lower early diabetic kidney disease
Fat tissue FABP4 higher; LPL lower insulin resistance
Gut LGALS4, MUC13, PRAP1 higher possibly medicines such as metformin

💬 Discuss: the effects barely changed in the sensitivity analyses, but the number of significant proteins ranged from 182 to 533. Which would you report, and why? (Choose the rule before looking; report the others as sensitivity analyses. Adding 119 plate terms to a 600-person model costs power.)

💬 Discuss: which of these are causes of diabetes, consequences (kidney damage), or treatment effects? UMOD’s pQTL sits in the UMOD gene, a region also linked to kidney function in large GWAS: an example of how pQTLs help ask about cause (Mendelian randomization).

Instructor notes

TipInstructor tip: timing and pitfalls
  • Use the 3–5 minute load in Part 4 for a break or for questions about Olink.
  • The protein IDs in the pQTL files look like P09769_ENSG00000000938.13: UniProt ID, then the gene’s Ensembl ID. The notebook matches on the UniProt part.
  • The plate boxplot sorts plates by their median, so it always rises left to right: teach students to look at how much, not whether.
  • The BMI challenge is a strong, quick lesson in confounding: leptin’s diabetes link almost disappears once BMI is in the model.

Key takeaways

  • Olink measures thousands of proteins with antibody pairs and DNA tags; NPX is relative and log₂
  • Filter huge files on the command line (awk) before R reads them
  • Data normalized for you still needs checking for batch effects
  • Blood proteins come from the whole body, so they show more than blood RNA
  • pQTLs link genetics to protein levels, and help ask about cause
